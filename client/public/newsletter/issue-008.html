① Main Story

Tearra's PRD Framework Is the Missing Link Between Your Idea and a Working Build

If you've been handing Claude Code vague instructions and wondering why the output is a mess, this is exactly what you've been missing.

A PRD is a Product Requirements Document. Think of it as a detailed instruction sheet you hand to Claude Code for one specific feature or phase of your build. Not the whole app at once — one piece at a time, in order. Each PRD tells Claude exactly what to build, what the data looks like, what the tech stack is, and what done actually means. When it's written right, Claude Code can execute it without guessing.

Tearra Spencer dropped her full system in the group and then walked everyone through it live in her class. The framework covers everything: how to open a strategy conversation, how to do competitive research before writing a single line of code, how to map the build, and then how to generate the CLAUDE.md project brief followed by every PRD in sequence. Her rule — one that matters — is that every PRD must be completely standalone. If PRD 7 touches a database table that PRD 2 defined, PRD 7 restates that full schema anyway. No cross-referencing. No 'see above.' Each file has to work on its own because you're handing it to Claude Code on its own.

The mistake most people make is treating Claude Code like a contractor who remembers everything from your last conversation. It doesn't. If you hand it a partial spec, it fills in the gaps with assumptions — and those assumptions will cost you hours of debugging. The other trap is scope creep before you even start building. Tearra's framework forces you to pressure-test the idea first, cut ruthlessly to the real MVP, and only write specs for what you've confirmed is worth building. Sherry Carter caught it live and said Claude put her in time out right after class, which honestly sounds about right — she was probably trying to build everything at once.

  • CLAUDE.md Goes First: Before any PRD, you create one project brief saved as CLAUDE.md in your repo root. It has the project name, the problem it solves, the full tech stack, and a numbered list of every PRD in build order. Claude Code always knows where it is.
  • One PRD at a Time, In Order: You do not hand Claude Code all your PRDs at once. PRD 1 first, confirm it works, then PRD 2. Each one is its own complete Markdown file. A simple build might be 6-7 PRDs. A complex one could be 20 or more.
  • Standalone or It Fails: Every PRD must include the full schema for every table it touches, even if a previous PRD already defined it. If it can't stand alone, it's a failed PRD. This is non-negotiable.
💼 How does this apply to your business?

Imagine you're building a client onboarding portal for a home care business — like what Carrien is doing with her non-medical home care company. Instead of dumping the whole concept on Claude Code and getting a half-broken mess back, you map it out: PRD 1 builds the foundation and auth, PRD 2 handles client intake forms, PRD 3 builds the new hire orientation flow. Each one ships clean before the next one starts. That's the difference between a build that actually works and one you're constantly patching.

③ Worth Knowing

Rotate Your API Keys. No, Actually Do It Right Now.

Natasha Brown dropped a security alert early Sunday morning — Composio had a May 2026 security incident and if you use Composio in any of your builds, your API keys may have been exposed. Nathan said he was going to do it immediately. Nathan was right. Composio is used by a lot of people in this group for connecting tools like email and calendar inside automations, so this wasn't a small thing.

Natasha's follow-up advice is worth making a habit: instead of rotating keys every 60 or 90 days, consider moving to a 30-day rotation schedule. Platforms get breached. It's always something, as HotRod put it. The best defense is making rotation a routine before you need it to be an emergency. While you're at it, Anthony flagged that bad infographics about tools like Claude are circulating online — his pro tip is to drop the image directly into Claude and ask it to check for legitimacy before you trust any advice from it.
